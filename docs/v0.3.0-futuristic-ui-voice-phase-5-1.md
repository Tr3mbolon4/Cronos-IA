# CRONOS v0.3.0 - Fase 5.1 Provider Local de Voz

## Objetivo

Esta fase corrige a premissa de STT da Fase 5. O CRONOS nao deve tratar `SpeechRecognition` do WebView como provider local, offline ou garantido. A arquitetura passa a selecionar `cronos-local-whisper` como provider oficial de STT e deixa `webview-speech-recognition` apenas como provider experimental, por escolha explicita.

## Decisao Tecnica

Provider oficial:

- ID: `cronos-local-whisper`
- Base recomendada: `whisper.cpp`/GGML
- Licenca do runtime: MIT
- Licenca dos pesos Whisper: MIT
- Execucao: local, CPU, offline
- Porta publica: nenhuma
- Servico Windows: nenhum
- Tarefa agendada: nenhuma
- Firewall: nenhuma regra
- Download automatico: proibido
- Audio persistido por padrao: nao

Modelo padrao recomendado:

- Arquivo: `ggml-base.bin`
- Idioma alvo: pt-BR
- Tamanho aproximado: 142 MB
- Escolha: melhor equilibrio inicial que `tiny` para portugues, com impacto menor que `small`
- Checksum: deve ser registrado no artefato final do release
- Local esperado no pacote: `voice/whisper/models/ggml-base.bin`

Runtime esperado:

- Binario: `whisper-cli.exe`
- Local esperado no pacote: `voice/whisper/whisper-cli.exe`
- Override de validacao: `CRONOS_LOCAL_WHISPER_DIR`

## Comparacao de Providers

`whisper.cpp` foi escolhido como primeira base porque tem runtime C/C++ pequeno, empacotamento direto no Windows, suporte CPU, ausencia de Python no runtime instalado e caminho claro para CUDA futuro. Whisper ONNX Runtime e faster-whisper permanecem opcoes futuras, mas adicionam mais dependencias no pacote inicial. Windows Speech local nao foi adotado como padrao porque a garantia offline e o contrato de disponibilidade variam por instalacao do Windows.

## Arquitetura Implementada

Arquivos principais:

- `frontend/src-tauri/src/lib.rs`
- `frontend/src/features/voice/types.ts`
- `frontend/src/features/voice/voiceStorage.ts`
- `frontend/src/features/voice/providers/webVoiceProviders.ts`
- `frontend/src/features/voice/useVoiceController.ts`
- `frontend/src/features/voice/components/VoiceSettingsPanel.tsx`

O comando Tauri `get_local_whisper_status` inspeciona o pacote instalado e retorna caminhos, modelo, checksum esperado e diagnostico. Ele nao inicia processo, nao abre porta e nao toca em audio.

O frontend:

- seleciona `cronos-local-whisper` por padrao;
- mostra `webview-speech-recognition` como experimental;
- bloqueia fallback silencioso para WebView;
- mantem texto funcional quando STT local esta indisponivel;
- cancela resultados tardios de transcricao;
- mantem TTS existente;
- preserva voz desligada por padrao.

## Formato de Audio Planejado

O provider local deve receber:

- mono;
- PCM WAV;
- 16 kHz;
- duracao maxima entre 30 e 60 segundos;
- uma transcricao por vez;
- timeout de transcricao;
- temporarios removidos ao finalizar, cancelar ou falhar.

A implementacao atual ainda nao habilita a ponte real PCM WAV porque o runtime/modelo nao estao presentes no pacote de validacao.

## Riscos Restantes

- O tamanho do instalador crescera ao incluir o modelo.
- `ggml-base.bin` pode ser insuficiente em ambientes ruidosos; `small` deve ser avaliado futuramente.
- A conversao WebView para PCM WAV 16 kHz precisa ser validada em Windows 10 e Windows 11.
- TTS `speechSynthesis` ainda depende do runtime WebView/vozes instaladas e precisa validacao empacotada.
