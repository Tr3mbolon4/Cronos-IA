# CRONOS v0.3.0 - Recuperacao Funcional do Nucleo Local

## Status

A evolucao de funcionalidades e a Fase 6 foram interrompidas. O foco atual e recuperar o nucleo funcional real do executavel desktop.

## Auditoria da resposta fixa

Texto encontrado:

`Estou rodando localmente no MVP do CRONOS. Ainda nao tenho um modelo de IA completo conectado...`

Origem anterior:

- arquivo: `backend/cronos/services/chat.py`
- funcao: `send_message`
- endpoint: `POST /chat`
- handler: `backend/cronos/server.py`
- condicao: sempre executava, sem verificar provider de IA
- tipo: resposta padrao hardcoded de MVP

Caminho real anterior:

frontend `useChatWorkspace.submitMessage`
-> `POST /chat`
-> `CronosHandler.do_POST`
-> `chat.send_message`
-> resposta fixa gravada como `assistant`
-> frontend exibia como se fosse resposta de IA.

Esse comportamento foi removido. Falhas de modelo local agora retornam erro claro:

`Nenhum modelo de IA local está instalado ou configurado.`

Uma falha de LLM nao deve mais ser salva ou exibida como resposta do assistente.

## Arquitetura aplicada nesta recuperacao

- `LLMProvider` abstrato criado no backend local.
- Provider inicial: `cronos-local-llama`.
- Runtime esperado: `llama.cpp` via `llama-server.exe`.
- Bind permitido: somente `127.0.0.1`.
- Recursos resolvidos pelo diretorio de recursos do Tauri, sem depender de `G:\Cronos-IA`.
- Runtime/modelo permanecem fora do Git.
- Manifest do LLM incluido em `frontend/src-tauri/resources/ai/llm/manifest.json`.
- Script administrativo criado: `scripts/prepare-local-llm.ps1`.

## Fluxo atual do Chat

1. Frontend envia mensagem para `POST /chat`.
2. Backend valida sessao.
3. Mensagem do proprietario e salva.
4. Historico recente e recuperado.
5. Retrieval local tenta buscar contexto documental.
6. Prompt do CRONOS e montado.
7. `llm_provider.generate` chama o provider local.
8. Resposta real e salva como `assistant`.
9. Sem modelo, o endpoint retorna erro 503.

## PDF e RAG

O endpoint legado `/documents/{id}/ask` nao gera mais sintese simulada quando ha citacoes. Ele envia o contexto documental ao mesmo provider local. Quando nenhuma citacao e encontrada, retorna:

`Nao encontrei essa informacao nos documentos selecionados.`

## Preparacao administrativa do LLM

O script `scripts/prepare-local-llm.ps1` valida:

- `RuntimeSha256` e `ModelSha256` com exatamente 64 caracteres hexadecimais;
- nome `llama-server.exe`;
- modelo `.gguf`;
- tamanho maior que zero e minimo seguro;
- rejeicao de ponteiro Git LFS;
- hash de origem;
- hash apos copia;
- manifest com integridade validada.

## Validacao real ja executada

- Runtime oficial `llama.cpp b10078` para Windows x64 importado fora do Git.
- `llama-server.exe --help` validado com exit code zero.
- Modelo `Qwen/Qwen2.5-1.5B-Instruct-GGUF` importado fora do Git com SHA-256 validado.
- Manifest do LLM atualizado com hashes e tamanhos reais, sem caminhos absolutos.
- Chat backend gerou respostas reais pelo modelo local, incluindo a resposta controlada `CRONOS FUNCIONANDO`.
- Historico recente do Chat passou a enviar ate 20 mensagens e um transcript numerado ao modelo.
- Provider real de embeddings via `llama.cpp --embedding` validado com o mesmo GGUF local.
- Embeddings nativos de 1536 dimensoes sao reduzidos para 384 dimensoes por media de grupos e normalizacao antes da persistencia.
- PDF sintetico de teste gerou 1 pagina, 1 chunk e 1 embedding real.
- RAG respondeu a chave `AZUL-4729`, sistema `CRONOS` e cor `verde`, com citacao de documento e pagina.
- Pergunta sem informacao documental sobre salario respondeu que a informacao nao foi encontrada.
