# CRONOS v0.2.0 - Fase 1: migrations e backup

Data: 2026-07-21
Branch: `feature/v0.2.0-memory-knowledge`
Tag de seguranca: `before-v0.2.0-memory-knowledge`

## Objetivo

Preparar a base segura da v0.2.0 sem alterar ainda os fluxos funcionais de memoria, biblioteca ou busca. Esta fase introduz migrations versionadas para o SQLite, backup automatico antes de migrations pendentes e testes de compatibilidade com bancos 0.1.x.

## Arquitetura implementada

Novos componentes:

- `backend/cronos/migrations/`: catalogo versionado de migrations.
- `backend/cronos/services/migration_service.py`: aplica migrations idempotentes, registra `schema_migrations` e interrompe a inicializacao em caso de falha.
- `backend/cronos/services/backup_service.py`: cria copia do banco antes de migrations pendentes.
- `backend/tests/test_migrations.py`: valida migracao de banco legado 0.1.x, idempotencia e falha segura.

O `init_db()` agora delega a preparacao do schema ao `migration_service`, preservando compatibilidade com o MVP existente.

## Migrations atuais

`0001_base_schema`

- Cria as tabelas base 0.1.x quando necessario: `owner`, `sessions`, `messages`, `documents`, `audit_log`.
- Usa `CREATE TABLE IF NOT EXISTS`, mantendo dados existentes.

`0002_memory_knowledge_schema`

- Cria as tabelas iniciais para a v0.2.0:
  - `memory_categories`
  - `memories`
  - `memory_revisions`
  - `memory_relations`
  - `document_sources`
  - `document_pages`
  - `document_chunks`
  - `document_embeddings`
- Insere categorias iniciais de memoria com `INSERT OR IGNORE`.

## Backups

Antes de aplicar migrations pendentes em um banco existente, o CRONOS cria backup em:

`%LOCALAPPDATA%\CRONOS\backups\database-migrations\`

Em ambiente de desenvolvimento/testes, o caminho equivalente fica dentro de `settings.data_dir/backups/database-migrations`.

Formato:

`cronos-before-migration-AAAAMMDDHHMMSS.db`

Se nao houver migration pendente, nenhum backup novo e criado.

## Comportamento em falha

As migrations sao executadas dentro de transacao. Se uma falha ocorrer:

- a inicializacao e interrompida com `MigrationError`;
- o banco original permanece legivel;
- o backup criado antes da tentativa permanece disponivel;
- migrations seguintes nao sao registradas em `schema_migrations`;
- tokens, PINs, senhas ou credenciais nao sao registrados em logs.

## Compatibilidade com bancos 0.1.x

Foi criado teste simulando um banco legado com as tabelas 0.1.x e dados existentes. A migracao preservou:

- proprietario;
- documento existente;
- tabelas base;
- banco original em arquivo de backup.

Depois da migracao, o banco passou a conter `schema_migrations` e as novas tabelas da v0.2.0.
